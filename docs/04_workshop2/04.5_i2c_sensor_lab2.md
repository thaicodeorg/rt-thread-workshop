## ความแตกต่างสำคัญ: SHT30 (Lab 2) vs BME280 (Lab 3)

| หัวข้อเปรียบเทียบ | SHT30 (Lab 2) | BME280 (Lab 3) |
| :--- | :--- | :--- |
| **รูปแบบการสื่อสาร** | **Command-based** (ส่งคำสั่ง 2 ไบต์ เช่น `0x2C, 0x06` แล้วรออ่าน) | **Register-based** (ต้องระบุหมายเลข Register ภายใน เช่น `0xD0`, `0xF4`, `0xF7`) |
| **I2C Address (7-bit)** | `0x44` (หรือ `0x45`) | **`0x76`** (หรือ **`0x77`** ขึ้นอยู่กับขา SDO) |
| **การตรวจสอบตัวตน** | ไม่มี Chip ID Register เฉพาะ | มี Register **`0xD0` (Chip ID)** ซึ่งต้องอ่านได้ค่า **`0x60`** เสมอ |
| **การคำนวณค่าจริง** | สูตรคณิตศาสตร์เชิงเส้นง่ายๆ (4 บรรทัด) | **ซับซ้อนมาก** ต้องอ่านค่า Calibration 26 ไบต์จากชิปมาเข้าสูตรชดเชยของ Bosch |

!!! tip "ทำไม BME280 ถึงควรใช้ Software Package?"
    ในการอ่านค่า BME280 หากเขียนเองทั้งหมดจะต้องอ่านค่า **Trimming Parameters (Calibration Data)** จาก Register `0x88–0xA1` และ `0xE1–0xF0` มาคำนวณชดเชยหลายสิบบรรทัด
    **แนวทางที่ดีที่สุดใน RT-Thread:** ใช้ `rt_i2c_transfer()` เพื่อทดสอบอ่าน **Chip ID (`0xD0`)** ให้เข้าใจหลักการ Register-based แล้วใช้ **Software Package (`bme280`)** สำหรับการอ่านค่าจริงครับ!

## การต่อสาย BME280 บน RA8D1 Vision Board (Header J4)

ใช้การตั้งค่า **Hardware IIC (`"i2c0"`)** ชุดเดิมจาก Lab 1 และ Lab 2 (ไม่ต้องแก้ RASC ใหม่หากเปิด `"i2c0"` ไว้แล้ว):

| ขาบนโมดูล BME280 | ต่อเข้ากับ Header J4 | ขาจริงชิป RA8D1 | หมายเหตุ |
| :--- | :--- | :--- | :--- |
| **VCC** | **Pin 1** หรือ **Pin 17** | **3.3V** | ห้ามต่อ 5V เด็ดขาด |
| **GND** | **Pin 6** หรือ **Pin 9** | **GND** | กราวด์ร่วม |
| **SCL** | **Pin 28** | **`P408`** (SCL0) | Hardware IIC0 |
| **SDA** | **Pin 27** | **`P409`** (SDA0) | Hardware IIC0 |
| *(CSB)* | *(ปล่อยลอย หรือต่อ 3.3V)* | - | บังคับให้โมดูลทำงานในโหมด I2C (ไม่ใช่ SPI) |
| *(SDO)* | *(ปล่อยลอย หรือต่อ GND)* | - | ต่อ GND = Address `0x76` / ต่อ 3.3V = Address `0x77` |

## Lab ส่วนที่ 1: ทดสอบอ่าน Chip ID (`0xD0`) ด้วย `rt_i2c_transfer()`

ส่วนนี้จำลองการทำงานเหมือน `Wire.beginTransmission()` + `Wire.requestFrom()` ใน Arduino เพื่อตรวจสอบว่า RA8D1 คุยกับ Register ของ BME280 ได้ถูกต้องหรือไม่

### โค้ดทดสอบใน `hal_entry.c` (หรือ `applications/main.c`)

```c
#include <rtthread.h>
#include <rtdevice.h>

#define BME280_I2C_BUS   "i2c0"
#define BME280_ADDR      0x76    // หากไม่เจอให้ลองเปลี่ยนเป็น 0x77
#define BME280_REG_ID    0xD0    // Register เก็บ Chip ID ของ BME280

static struct rt_i2c_bus_device *i2c_bus = RT_NULL;

/* ฟังก์ชันอ่านข้อมูล 1 ไบต์ จาก Register ที่ระบุ */
static rt_err_t bme280_read_reg(rt_uint8_t reg, rt_uint8_t *data)
{
    struct rt_i2c_msg msgs;

    // ข้อความที่ 1: เขียนหมายเลข Register ที่ต้องการอ่าน (0xD0)
    msgs.addr  = BME280_ADDR;
    msgs.flags = RT_I2C_WR;
    msgs.buf   = &reg;
    msgs.len   = 1;

    // ข้อความที่ 2: อ่านค่า 1 ไบต์กลับมา
    msgs.addr  = BME280_ADDR;
    msgs.flags = RT_I2C_RD;
    msgs.buf   = data;
    msgs.len   = 1;

    // ส่งทั้ง 2 ข้อความต่อเนื่องกัน (Repeated Start)
    if (rt_i2c_transfer(i2c_bus, msgs, 2) == 2)
    {
        return RT_EOK;
    }
    return -RT_ERROR;
}

void hal_entry(void)
{
    rt_uint8_t chip_id = 0;

    i2c_bus = (struct rt_i2c_bus_device *)rt_device_find(BME280_I2C_BUS);
    if (i2c_bus == RT_NULL)
    {
        rt_kprintf("I2C bus (%s) not found!\n", BME280_I2C_BUS);
        return;
    }

    rt_kprintf("=== BME280 Register Check Lab ===\n");

    if (bme280_read_reg(BME280_REG_ID, &chip_id) == RT_EOK)
    {
        rt_kprintf("Read Chip ID: 0x%02X ", chip_id);
        if (chip_id == 0x60)
        {
            rt_kprintf("-> [OK] Found genuine BME280!\n");
        }
        else if (chip_id == 0x58)
        {
            rt_kprintf("-> [WARN] This is BMP280 (No Humidity sensor)!\n");
        }
    }
    else
    {
        rt_kprintf("Failed to read BME280! Check address (0x76/0x77) or wiring.\n");
    }
}
```

!!! note "ข้อสังเกตจาก Chip ID"
    - ถ้าอ่านได้ **`0x60`** = เป็นชิป **BME280** แท้ (วัดได้ 3 ค่า: อุณหภูมิ, ความชื้น, ความกดอากาศ)
    - ถ้าอ่านได้ **`0x58`** = โมดูลที่ซื้อมาเป็นรุ่น **BMP280** (วัดได้เฉพาะอุณหภูมิและความกดอากาศ ไม่มีเซ็นเซอร์ความชื้น)

## Lab ส่วนที่ 2: อ่านค่าจริงทั้ง 3 ค่าด้วย RT-Thread Sensor Framework (`bme280` Package)

ใน RT-Thread มีระบบมาตรฐานกลางที่ชื่อว่า **Sensor Framework** ซึ่งจะห่อหุ้มเซ็นเซอร์ทุกชนิด (ไม่ว่าจะเป็น I2C หรือ SPI) ให้กลายเป็น Device ชื่อเดียวกัน เช่น `temp_bme`, `humi_bme`, `baro_bme`

### ขั้นตอนที่ 1: ติดตั้งแพ็กเกจ `bme280`
1. เปิด **RT-Thread Settings → Software Packages → IoT - internet of things → sensors**
2. ค้นหาและติ๊กเลือก **`bme280: Digital humidity, pressure and temperature sensor`**
3. ตรวจสอบใน **Hardware → On-chip Peripheral Drivers** ว่าเปิด **`Enable Sensor Framework`** แล้ว (ปกติระบบจะเปิดให้อัตโนมัติเมื่อเลือกแพ็กเกจ)
4. กด **Ctrl+S** เพื่อบันทึกและดาวน์โหลดแพ็กเกจ

### ขั้นตอนที่ 2: เขียนโค้ดลงทะเบียนและอ่านค่า (`hal_entry.c`)

```c
#include <rtthread.h>
#include <rtdevice.h>
#include "sensor_bosch_bme280.h"  // Header ของแพ็กเกจ BME280

#define BME280_I2C_BUS   "i2c0"

/* 1. ลงทะเบียนเซ็นเซอร์เข้าสู่ RT-Thread Sensor Framework อัตโนมัติตอนบูต */
static int rt_hw_bme280_port(void)
{
    struct rt_sensor_config cfg;

    cfg.intf.dev_name = BME280_I2C_BUS;
    cfg.intf.user_data = (void *)BME280_ADDR_DEFAULT; // 0x76 (หรือใช้ BME280_ADDR_ALTERNATE สำหรับ 0x77)

    rt_hw_bme280_init("bme280", &cfg);
    return RT_EOK;
}
INIT_ENV_EXPORT(rt_hw_bme280_port);

/* 2. อ่านค่าผ่านคำสั่งมาตรฐานของ Sensor Framework */
void hal_entry(void)
{
    rt_device_t temp_dev, humi_dev, baro_dev;
    struct rt_sensor_data temp_data, humi_data, baro_data;

    // ค้นหา Device ทั้ง 3 ตัวที่แพ็กเกจสร้างให้
    temp_dev = rt_device_find("temp_bme");
    humi_dev = rt_device_find("humi_bme");
    baro_dev = rt_device_find("baro_bme");

    if (!temp_dev || !humi_dev || !baro_dev)
    {
        rt_kprintf("BME280 sensor devices not found!\n");
        return;
    }

    // เปิดใช้งาน Device
    rt_device_open(temp_dev, RT_DEVICE_FLAG_RDONLY);
    rt_device_open(humi_dev, RT_DEVICE_FLAG_RDONLY);
    rt_device_open(baro_dev, RT_DEVICE_FLAG_RDONLY);

    rt_kprintf("=== BME280 Sensor Framework Lab ===\n");

    while (1)
    {
        // อ่านค่าผ่าน rt_device_read() เหมือนอ่านไฟล์
        rt_device_read(temp_dev, 0, &temp_data, 1);
        rt_device_read(humi_dev, 0, &humi_data, 1);
        rt_device_read(baro_dev, 0, &baro_data, 1);

        // ค่าที่ได้จาก Sensor Framework จะคูณ 10 ไว้ (เพื่อเลี่ยงการใช้ Float)
        rt_kprintf("Temp: %d.%d C | Humi: %d.%d %% | Press: %d Pa\n",
                   temp_data.data.temp / 10, temp_data.data.temp % 10,
                   humi_data.data.humi / 10, humi_data.data.humi % 10,
                   baro_data.data.baro);

        rt_thread_mdelay(2000);
    }
}
```

### ตัวอย่าง Output (บน Serial Terminal 115200 bps)

```text
=== BME280 Sensor Framework Lab ===
Temp: 26.4 C | Humi: 55.8 % | Press: 100842 Pa
Temp: 26.5 C | Humi: 55.7 % | Press: 100840 Pa
```

## ทดสอบผ่าน FinSH Shell (ไม่ต้องเขียนโค้ดอ่านค่าเอง!)

```bash
list device                  # จะเห็น temp_bme, humi_bme, baro_bme เพิ่มขึ้นมา

sensor probe baro_bme        # สั่งสลับไปอ่านค่าความกดอากาศ
sensor read
```

??? failure "แก้ปัญหาเบื้องต้นเฉพาะ BME280"
    **"Failed to read BME280" หรือ `i2c scan i2c0` ไม่เจออุปกรณ์**
    - **เช็ก Address:** โมดูล BME280 ในท้องตลาดมี 2 Address คือ **`0x76`** (ส่วนใหญ่) และ **`0x77`** ให้ลองสลับค่า `BME280_ADDR` หรือ `BME280_ADDR_ALTERNATE`
    - **เช็กขา CSB:** โมดูล BME280 แบบ 6 ขา (ที่มีขา CSB และ SDO) หากปล่อยขา CSB ลอยไว้ บางบอร์ดอาจไม่เข้าโหมด I2C ให้ลองต่อขา **CSB เข้ากับ 3.3V**

    **"Compiler แจ้ง Error: `sensor_bosch_bme280.h: No such file or directory`"**
    - หลังจากติ๊กเลือกแพ็กเกจ `bme280` ใน RT-Thread Settings แล้ว ต้องกด **Ctrl+S** เพื่อบันทึกและรอให้ IDE ดาวน์โหลดไฟล์ลงโฟลเดอร์ `packages/` ให้เสร็จสมบูรณ์ก่อนกด Build

    **"ได้ชิป BMP280 (`0x58`) มาแทน BME280 (`0x60`)"**
    - หากแพ็กเกจ `bme280` แจ้งเตือน Chip ID mismatch ให้เข้าไปตั้งค่าในเมนูย่อยของแพ็กเกจ `bme280` ใน **RT-Thread Settings** หรือใช้แพ็กเกจที่รองรับทั้งคู่ (เช่น `bmp280` / `bmx280`)
