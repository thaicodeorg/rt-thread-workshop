# `hal_entry.c` vs `main.c`: โปรเจกต์แบบไหนใช้อันไหน

<span class="md-tag">Foundation</span> <span class="md-tag">Architecture</span> <span class="md-tag">Project Structure</span>

> 💡 **ทำไมบทนี้ถึงสำคัญ?**
> ผู้เริ่มต้นที่ย้ายมาจาก Arduino, ESP32 หรือ STM32 มักจะสะดุดตั้งแต่วินาทีแรกที่สร้างโปรเจกต์บนบอร์ด RA8D1 เพราะ **"หาไฟล์ `main.c` ไม่เจอ!"** บทนี้จะไขข้อข้องใจทั้งหมดและช่วยให้คุณวางโครงสร้างโค้ดได้อย่างมืออาชีพตั้งแต่เริ่มต้น

## สิ่งที่คุณจะเข้าใจหลังอ่านหน้านี้

- [ ] ทำไมเทมเพลตโปรเจกต์ของ RA8D1 บางตัวไม่มี `applications/main.c`
- [ ] ลำดับการบูตจริงของ **RT-Thread Kernel** ร่วมกับ **Renesas FSP**
- [ ] ความจริงที่หลายคนเข้าใจผิดเกี่ยวกับสิทธิ์ของ `hal_entry()` ในระบบ RTOS
- [ ] แนวทางการเลือกและขยายโครงสร้างไฟล์เมื่อโปรเจกต์โตขึ้น (จาก Lab เล็กๆ สู่ระบบ IoT/AI เต็มรูปแบบ)

## ปัญหาที่พบบ่อย: สร้างโปรเจกต์แล้วไม่เจอ `applications/main.c`

เมื่อคุณสร้างโปรเจกต์ต้นแบบ (เช่น `vision_board_blink_led`) บน RT-Thread Studio คุณจะพบโครงสร้างโฟลเดอร์แบบนี้:

```text
vision_board_blink_led/
├── src/
│   └── hal_entry.c          ← มีไฟล์นี้ไฟล์เดียวสำหรับเขียนโค้ด!
├── ra/                      ← ไลบรารีมาตรฐาน Renesas FSP
├── ra_gen/                  ← โค้ดตั้งค่า Pin/Clock จาก RASC
├── libraries/               ← ตัวเชื่อม HAL Drivers ของ RT-Thread
├── rt-thread/               ← ซอร์สโค้ดหลักของ RT-Thread OS
└── ...

❌ ไม่มีโฟลเดอร์ applications/
❌ ไม่มีไฟล์ main.c
```

**ทำไมถึงเป็นแบบนี้?** คำตอบไม่ได้อยู่ที่ว่าโปรเจกต์นี้ไม่ใช่ RT-Thread แต่อยู่ที่ **การออกแบบจุดเชื่อมต่อ (Entry Point) ระหว่าง RT-Thread กับ Renesas FSP** ครับ

---

## เจาะลึกกลไกการบูต: `main()` และ `hal_entry()` ทำงานร่วมกันอย่างไร?

ในชิปตระกูล **Renesas RA (รวมถึง RA8D1)** บริษัท Renesas กำหนดมาตรฐานไว้ว่าโค้ดแอปพลิเคชันของผู้ใช้ควรเริ่มต้นที่ฟังก์ชัน `hal_entry()` เพื่อให้เป็นอิสระจากการตั้งค่าฮาร์ดแวร์ระดับล่าง

เมื่อทีมพัฒนา **RT-Thread** นำระบบปฏิบัติการมาครอบทับ Renesas FSP จึงได้ออกแบบลำดับการทำงานตอนเปิดเครื่อง (Boot Sequence) ดังนี้:

```text
[1. เปิดเครื่อง / Reset]
       │
       ▼
[2. rtthread_startup()]   ◀── ระบบปฏิบัติการ RT-Thread เริ่มทำงาน ตั้งค่า Heap และ Scheduler
       │
       ▼
[3. สร้าง Main Thread]    ◀── RT-Thread สร้าง Thread หลักขึ้นมาชื่อ "main" และเรียกฟังก์ชัน main()
       │
       ▼
[4. เรียก hal_entry()]    ◀── ฟังก์ชัน main() ของ Renesas BSP ส่งไม้ต่อเข้ามาที่ hal_entry()
```

!!! success "ความจริงสำคัญที่ต้องรู้!"
    **`hal_entry()` รันอยู่ภายใน "Main Thread" ของ RT-Thread Scheduler เต็มรูปแบบ!**
    - ไม่ใช่ Bare-metal ที่ไม่มี OS ดูแล
    - คุณสามารถสั่งสร้าง Thread ใหม่ (`rt_thread_create`), ใช้ `rt_thread_mdelay()`, ใช้ Mutex/Semaphore และเรียกใช้ Software Packages ทุกตัวใน `hal_entry()` ได้เหมือนใน `main()` ทุกประการ!

## 2 รูปแบบโครงสร้างโปรเจกต์ที่พบบน RT-Thread Studio

แม้เบื้องหลังจะรันบน Main Thread เหมือนกัน แต่ในหน้าต่าง Project Explorer คุณจะพบการจัดวางไฟล์ได้ 2 รูปแบบ:

### รูปแบบที่ 1: FSP Native Style (รวมศูนย์ที่ `src/hal_entry.c`)

เป็นรูปแบบเริ่มต้นของเทมเพลต Renesas RA ส่วนใหญ่ เพื่อให้ผู้ที่คุ้นเคยกับเครื่องมือของ Renesas (e2 studio / FSP) สามารถก๊อปปี้โค้ดตัวอย่างมาวางใน `hal_entry.c` ได้ทันที

```text
โปรเจกต์/
├── src/
│   └── hal_entry.c          ← เขียนโค้ดเริ่มต้นทั้งหมดที่นี่
├── ra_gen/
└── ...
```

**ตัวอย่างโค้ด (`src/hal_entry.c`):**

```c
#include <rtthread.h>
#include <rtdevice.h>
#include "hal_data.h"

#define LED_PIN    BSP_IO_PORT_01_PIN_02

void hal_entry(void)
{
    rt_kprintf("Hello from hal_entry() running on RT-Thread Main Thread!\n");

    while (1)
    {
        rt_pin_write(LED_PIN, PIN_HIGH);
        rt_thread_mdelay(500);  // คืน CPU ให้ Thread อื่นทำงานได้ตามปกติ
        rt_pin_write(LED_PIN, PIN_LOW);
        rt_thread_mdelay(500);
    }
}
```

---

### รูปแบบที่ 2: RT-Thread Standard Style (แยกโฟลเดอร์ `applications/`)

เป็นโครงสร้างมาตรฐานกลางของ RT-Thread ที่ใช้ร่วมกันทุกยี่ห้อ (STM32, ESP32, RISC-V, NXP) มักพบในเทมเพลตที่มีความซับซ้อนสูง เช่น `vision_board_wifi`, `vision_board_openmv` หรือ `vision_board_lvgl`

```text
โปรเจกต์/
├── applications/
│   ├── main.c               ← เขียนโค้ดแอปพลิเคชันหลักที่นี่
│   ├── sensor_task.c        ← แยกไฟล์ตามหน้าที่ได้เป็นระเบียบ
│   └── wifi_task.c
├── src/
│   └── hal_entry.c          ← ทำหน้าที่เป็นทางผ่าน หรือไม่ถูกเรียกใช้ตรงๆ
└── ...
```

**ตัวอย่างโค้ด (`applications/main.c`):**

```c
#include <rtthread.h>

int main(void)
{
    rt_kprintf("Hello from standard RT-Thread main()!\n");

    while (1)
    {
        rt_thread_mdelay(1000);
    }
    return 0;
}
```

## ตารางเปรียบเทียบแบบเจาะลึก

| หัวข้อเปรียบเทียบ | รูปแบบที่ 1: FSP Native (`hal_entry.c`) | รูปแบบที่ 2: RT-Thread Std (`applications/main.c`) |
| :--- | :--- | :--- |
| **มีโฟลเดอร์ `applications/`?** | ❌ ไม่มี | ✅ มี |
| **จุดเขียนโค้ดเริ่มต้น** | ฟังก์ชัน `hal_entry()` ใน `src/hal_entry.c` | ฟังก์ชัน `main()` ใน `applications/main.c` |
| **สถานะในระบบ RTOS** | รันบน **Main Thread** (มี Scheduler ดูแล) | รันบน **Main Thread** (มี Scheduler ดูแล) |
| **ใช้คำสั่ง RTOS / Packages** | ✅ ใช้ได้ครบถ้วน | ✅ ใช้ได้ครบถ้วน |
| **ความสะดวกในการขยายทีม** | ⚠️ เหมาะกับไฟล์เดียวหรือโค้ดสั้นๆ | ✅ จัดหมวดหมู่ไฟล์แยกโมดูลได้ง่ายกว่า |
| **ความเข้ากันได้ข้ามบอร์ด** | เฉพาะตระกูล Renesas RA | ย้ายโค้ดไปบอร์ด STM32 / RISC-V ได้ง่าย |

## แนวทางการเลือกใช้ในแต่ละสถานการณ์

### 1. ใช้ `src/hal_entry.c` (รูปแบบที่ 1) เมื่อ:
* กำลังเรียน **Workshop พื้นฐาน** (เช่น Blink LED, อ่านเซ็นเซอร์ I2C/SPI, ทดสอบ GPIO Interrupt)
* ต้องการนำโค้ดตัวอย่างของ **Renesas FSP** มาทดสอบร่วมกับ RT-Thread อย่างรวดเร็ว
* โปรเจกต์มีขนาดเล็ก-กลาง และไม่ต้องการสร้างโฟลเดอร์ใหม่ให้ยุ่งยาก

### 2. ใช้ `applications/main.c` (รูปแบบที่ 2) เมื่อ:
* พัฒนา **โปรเจกต์จริงขนาดใหญ่** ที่มีหลายระบบทำงานพร้อมกัน (เช่น กล้อง OpenMV + จอ LVGL + ส่งข้อมูล MQTT ขึ้น Cloud)
* ต้องการสร้างโครงสร้างไฟล์ที่เป็นมาตรฐานเดียวกับบอร์ดยี่ห้ออื่นๆ ในทีมพัฒนา

## เคล็ดลับระดับโปร: ขยายโค้ดในรูปแบบที่ 1 โดยไม่ต้องยัดทุกอย่างไว้ใน `hal_entry.c`

หากคุณเริ่มต้นจากเทมเพลตที่มีแค่ `src/hal_entry.c` แล้วโปรเจกต์เริ่มใหญ่ขึ้น **คุณไม่จำเป็นต้องสร้างโปรเจกต์ใหม่!** RT-Thread มีกลไกที่เรียกว่า **Automatic Initialization (`INIT_APP_EXPORT`)** ที่ให้คุณแยกไฟล์ `.c` ใหม่ๆ ออกมาได้ทันที:

```c title="my_sensor_module.c — แยกไฟล์ใหม่ในโฟลเดอร์ src/"
#include <rtthread.h>

static void sensor_thread_entry(void *parameter)
{
    while (1)
    {
        rt_kprintf("Reading sensor in background thread...\n");
        rt_thread_mdelay(2000);
    }
}

/* ฟังก์ชันนี้จะถูก RT-Thread เรียกทำงานอัตโนมัติก่อนเข้า hal_entry()! */
static int my_sensor_init(void)
{
    rt_thread_t tid = rt_thread_create("sensor", sensor_thread_entry, RT_NULL, 1024, 20, 10);
    if (tid != RT_NULL)
    {
        rt_thread_startup(tid);
    }
    return RT_EOK;
}
INIT_APP_EXPORT(my_sensor_init); // <-- บรรทัดมหัศจรรย์ของ RT-Thread!
```

> 🚀 **ผลลัพธ์:** โค้ดอ่านเซ็นเซอร์ของคุณจะแยกไฟล์อย่างเป็นระเบียบและรันเป็น Thread อิสระทันทีตอนเปิดเครื่อง โดยไม่ต้องแก้ไขไฟล์ `hal_entry.c` แม้แต่บรรทัดเดียว!

## สรุปสั้นๆ ให้จำขึ้นใจ

```text
1. เปิดโปรเจกต์มาเจอแค่ src/hal_entry.c  ──▶ เขียนโค้ดใน hal_entry() ได้เลย (มันคือ Main Thread ของ RT-Thread!)
2. เปิดโปรเจกต์มาเจอ applications/main.c ──▶ เขียนโค้ดใน main() ตามมาตรฐานสากล
3. เมื่อโค้ดเริ่มเยอะในไฟล์เดียว          ──▶ แยกไฟล์ใหม่แล้วใช้ INIT_APP_EXPORT() สร้าง Thread อัตโนมัติ
```

??? question "คำถามที่พบบ่อย (FAQ)"
    **"ใน `hal_entry()` ถ้าเผลอเขียน `while(1)` โดยไม่ใส่ `rt_thread_mdelay()` จะเกิดอะไรขึ้น?"**
    - เนื่องจาก `hal_entry()` รันอยู่บน Main Thread ของ RT-Thread หากคุณวนลูป `while(1)` เปล่าๆ โดยไม่เรียกฟังก์ชันที่คืนสิทธิ์ CPU (เช่น `rt_thread_mdelay()`) จะทำให้ Thread อื่นที่มี Priority ต่ำกว่า Main Thread ไม่ได้ทำงาน (เกิดอาการ Thread Starvation) ดังนั้น **ในลูป `while(1)` ของ RTOS ต้องมี `rt_thread_mdelay()` เสมอ**

    **"จะเปลี่ยนโปรเจกต์รูปแบบที่ 1 ให้มีโฟลเดอร์ `applications/main.c` ทำได้ไหม?"**
    - ทำได้ครับ เพียงคลิกขวาที่โปรเจกต์ → สร้างโฟลเดอร์ชื่อ `applications` (หรือใส่ไฟล์ใน `src/`) จากนั้นตั้งชื่อฟังก์ชันว่า `int main(void)` ได้เลย แต่ต้องตรวจสอบในไฟล์ `ra_gen/main.c` ของ Renesas ก่อนว่าไม่ได้ประกาศฟังก์ชัน `main()` ซ้ำซ้อนกัน (หากมีอยู่แล้ว ให้ใช้ `hal_entry()` เป็นจุดเริ่มต้นจะปลอดภัยที่สุด)

    **"ทำไมบาง Package ใน RT-Thread Settings ถึงบอกว่าต้องเรียกใช้ใน `main()`?"**
    - เอกสารของ Package เหล่านั้นเขียนอ้างอิงจากบอร์ดทั่วไปที่เริ่มทำงานที่ `main()` แต่บนบอร์ด Renesas RA เนื่องจาก `main()` วิ่งเข้ามาที่ `hal_entry()` คุณจึงสามารถนำโค้ดตัวอย่างที่เขาเขียนไว้ใน `main()` มาวางใน `hal_entry()` แล้วใช้งานได้ทันที 100%
