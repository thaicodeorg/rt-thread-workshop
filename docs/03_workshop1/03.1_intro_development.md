แนวทางการพัฒนาบนบอร์ด **Renesas RA8D1 Vision Board** ด้วยระบบปฏิบัติการ **RT-Thread** ครอบคลุมตั้งแต่การตั้งค่าเครื่องมือ (Toolchain), การกำหนดค่าฮาร์ดแวร์ (Peripheral), การเชื่อมต่อระบบเครือข่ายและหน้าจอ GUI ไปจนถึงสถาปัตยกรรมของแอปพลิเคชัน

[ข้อมูลทางเทคนิคของชิป Renesas RA8D1 pdf](./docs/ra8d1-flyer-r01pm0092eu0100-en.pdf)

## สรุปสเปกฮาร์ดแวร์สำคัญของ Vision Board (R7FA8D1BHECBD)  
- MCU: Renesas RA8D1 (Arm Cortex-M85 @ 480 MHz, 2MB Flash, 1MB SRAM, 2D Drawing Engine / Dave2D)   
- Memory ภายนอก: 32MB SDRAM, 16MB SPI Nor Flash, ช่องเสียบ MicroSD Card
- Camera & Display: กล้อง OV5640 / OV2640 (ผ่านอินเทอร์เฟซ CEU 16-bit), พอร์ตจอ MIPI-DSI / RGB LCD (4.3" / 7" Touch Screen)   
- Connectivity: โมดูล Wi-Fi + BLE (RW007 / Onboard Wireless), พอร์ต USB-DBG (DAP-Link), พอร์ต USB-OTG (High Speed)
- Expansion: ขา Pin Header 40-pin (รองรับ Arduino / Raspberry Pi HAT pinout บางส่วน), Pmod, CAN FD, Ethernet (ผ่านบอร์ดเสริม)
---

### 1. การตั้งค่าฮาร์ดแวร์และเครื่องมือพัฒนา (Hardware & Toolchain Setup)

บอร์ด Vision Board ใช้ชิปไมโครคอนโทรลเลอร์ **Renesas R7FA8D1BHECBD** (ซีพียู Arm Cortex-M85 ความเร็ว 480 MHz พร้อมชุดคำสั่ง Helium SIMD และหน่วยประมวลผลกราฟิก Dave2D GPU)

* **IDE หลัก:** **RT-Thread Studio** ร่วมกับแพ็กเกจ `sdk-bsp-ra8d1-vision-board` (RT-Thread v5.0.2 ขึ้นไป)
* **ตัวกำหนดค่าฮาร์ดแวร์:** **RA Smart Configurator (RASC)** (เช่น เวอร์ชัน `v2026-07` คู่กับ FSP `v6.6.0`) ซึ่งสามารถเรียกเปิดใช้งานได้โดยตรงจาก RT-Thread Studio ผ่านไฟล์ `configuration.xml` เพื่อตั้งค่า Clock, การเลือกขาพิน (Pin Muxing) และไดรเวอร์ FSP HAL
* **การอัปโหลดโปรแกรมและดีบัก (Flashing & Debugging):** เชื่อมต่อผ่านพอร์ต **USB-DBG** (วงจร DAP-Link บนบอร์ด) โดยใช้ **PyOCD** ($\ge 0.2.3$) ส่วนหน้าต่างคำสั่ง FinSH console จะสื่อสารผ่านพอร์ต Virtual COM ของ DAP-Link ที่ความเร็ว `115200` baud

---

### 2. โครงสร้างโปรเจกต์และการคอมไพล์ (SCons + FSP)

ส่วนของ BSP (`bsp/renesas/ra8d1-vision-board`) ทำหน้าที่เชื่อมโยงเคอร์เนลของ RT-Thread เข้ากับไดรเวอร์ Renesas Flexible Software Package (FSP):

* `board/ra8d1/configuration.xml` — ไฟล์โปรเจกต์ของ RASC สำหรับกำหนดค่าอุปกรณ์ต่อพ่วงของ FSP (`g_uartX`, `g_i2c_masterX`, `g_icuX` ฯลฯ) เมื่อกด Generate Code ใน RASC ระบบจะสร้างไฟล์ไดรเวอร์ระดับล่างไว้ในโฟลเดอร์ `board/ra8d1/ra_gen/` และ `ra_cfg/`
* `board/SConscript` และ `rtconfig.h` — ส่วนตั้งค่า RT-Thread Settings (`menuconfig`) สำหรับเปิดใช้งานไดรเวอร์อุปกรณ์ (`RT_USING_UART`, `RT_USING_I2C`, `RT_USING_PIN`, `RT_USING_WIFI`) ซึ่งจะไปเรียกใช้ Wrapper ของ FSP ในโฟลเดอร์ `libraries/HAL_Drivers/`
* `applications/hal_entry.c` — จุดเริ่มต้นการทำงานของแอปพลิเคชัน (`hal_entry()`) ที่ถูกเรียกหลังจาก Scheduler ของ RT-Thread เริ่มทำงาน ใช้สำหรับสร้างเธรด (Threads), ออบเจกต์ IPC และบริการเครือข่ายต่างๆ

### 3. ขั้นตอนการพัฒนาอุปกรณ์ต่อพ่วงและการสื่อสารหลัก

#### A. การอ่านค่าเซนเซอร์อุตสาหกรรมผ่าน Modbus RTU (RS485)

1. **RASC:** เปิดใช้งานช่องสัญญาณ SCI UART (เช่น `g_uart3`) กำหนดขา TX/RX และตั้งค่าขา GPIO 1 ขาสำหรับควบคุมทิศทางการรับ-ส่งข้อมูล (`DE/RE`) ของชิป MAX485
2. **RT-Thread Settings:** เปิดใช้งานแพ็กเกจ `agile_modbus` หรือ `freemodbus` ร่วมกับ `RT_USING_SERIAL`
3. **รูปแบบการทำงาน:** สร้างเธรดแยกเฉพาะสำหรับวนอ่านค่า (`rt_thread_create`) เพื่อดึงข้อมูลจาก Holding/Input Registers ตามรอบเวลาที่กำหนด (`rt_thread_mdelay`) แล้วส่งชุดข้อมูลเซนเซอร์ไปยัง Mailbox (`rt_mb_send`) หรือ Message Queue (`rt_mq_send`) เพื่อให้ส่วนส่งข้อมูลขึ้นคลาวด์และหน้าจอ UI นำไปใช้งานต่อ

#### B. การเชื่อมต่อ Wi-Fi, lwIP และ ThingsBoard MQTT (Telemetry & RPC)

1. **ระบบเครือข่าย:** โมดูล Wi-Fi บนบอร์ดจะลงทะเบียนผ่านเฟรมเวิร์ก WLAN ของ RT-Thread (`rt_wlan_connect`) ซึ่งทำงานอยู่บน **SAL (Socket Abstraction Layer)** และ **lwIP**
2. **MQTT Client:** เปิดใช้งานแพ็กเกจ **Paho MQTT** (`PKG_USING_PAHOMQTT`)
3. **การรับ-ส่งข้อมูล Telemetry และคำสั่ง RPC:**
* **การส่งข้อมูล (Publish):** จัดรูปแบบค่าที่อ่านได้จากเซนเซอร์เป็น JSON แล้วส่งไปยัง Topic `v1/devices/me/telemetry`
* **การรับคำสั่งควบคุมรีเลย์/อุปกรณ์ (Subscribe):** ติดตาม Topic `v1/devices/me/rpc/request/+` ภายในฟังก์ชัน Callback ให้แยกวิเคราะห์ค่า `method` และ `params` จาก JSON เพื่อสั่งเปิด-ปิดขา GPIO หรือโมดูลขยายพอร์ตรีเลย์ I2C จากนั้นส่งข้อความยืนยันกลับไปยัง `v1/devices/me/rpc/response/<request_id>`



#### C. การสร้างหน้าจอ LVGL GUI ด้วย SquareLine Studio

1. **จอแสดงผลและ GPU:** เปิดใช้งานไดรเวอร์จอ MIPI-DSI / RGB LCD และตัวเร่งความเร็วกราฟิก **Dave2D** ใน RASC คู่กับการเปิดใช้งาน **LVGL v9** ใน RT-Thread Settings
2. **ขั้นตอนการทำ UI:**
* ส่งออก (Export) ไฟล์โค้ดภาษา C จาก **SquareLine Studio** มาไว้ในโฟลเดอร์ `applications/ui/`
* แก้ไขไฟล์ `applications/SConscript` เพื่อรวมไฟล์ `.c` และ Path ของไฟล์ Header ที่สร้างขึ้นใหม่เข้าสู่ระบบคอมไพล์
* ให้การอัปเดตวิดเจ็ตบนหน้าจอทั้งหมด (เช่น `lv_label_set_text()`) ทำงานอยู่ภายในเธรดหลักของ LVGL เพียงเธรดเดียว (โดยดึงข้อมูลมาจาก Queue หรือ Struct ที่ป้องกันด้วย Mutex ซึ่งอัปเดตโดยเธรดเซนเซอร์หรือ MQTT) เพื่อป้องกันปัญหาข้อมูลชนกัน (Race Conditions)



#### D. งานด้าน Machine Vision (OpenMV / Edge Inference)

* หากต้องการรันระบบประมวลผลภาพด้วย MicroPython (เช่น อ่าน QR/Barcode, ตรวจจับสี, ตรวจจับใบหน้า) ให้แฟลชโปรเจกต์ `vision_board_openmv` จากโฟลเดอร์ `sdk-bsp-ra8d1-vision-board/projects/` แล้วเชื่อมต่อกับโปรแกรม **OpenMV IDE** ผ่านพอร์ต **USB-OTG**
* สำหรับงานประมวลผลภาพด้วยภาษา C/C++ ที่ทำงานร่วมกับทาสก์ของ RT-Thread ให้เรียกใช้ไดรเวอร์กล้อง CEU (`drv_ceu.c`) ร่วมกับชุดคำสั่งเร่งความเร็ว CMSIS-NN / Helium DSP

### 4. โครงสร้างเธรดและ IPC ที่แนะนำ

เพื่อให้ระบบรับ-ส่งข้อมูล Telemetry และหน้าจอ HMI บน RA8D1 ทำงานได้อย่างลื่นไหลและตอบสนองรวดเร็ว:

| ชื่อเธรด (Thread) | ลำดับความสำคัญ (Priority) | ขนาด Stack | หน้าที่ความรับผิดชอบ |
| --- | --- | --- | --- |
| **`lvgl_thread`** | ปานกลาง (เช่น 15) | 8–16 KB | เรียกฟังก์ชัน `lv_timer_handler()` ทุกๆ 5–10 ms และเรนเดอร์ UI ผ่าน Dave2D |
| **`sensor_thread`** | สูง (เช่น 10) | 2–4 KB | วนอ่านค่าจากเซนเซอร์ RS485/Modbus และ I2C แล้วส่งข้อมูลเข้า `rt_mq` |
| **`mqtt_thread`** | ปานกลาง (เช่น 12) | 4–6 KB | ดูแลการเชื่อมต่อ Wi-Fi อัตโนมัติ, ส่งข้อมูล Telemetry และรับคำสั่ง RPC ควบคุมรีเลย์ |
| **`finsh` (tshell)** | ต่ำ (20) | 4 KB | หน้าต่างคำสั่งตรวจสอบระบบ (`ps`, `free`, `wifi status` และคำสั่งที่สร้างเองผ่าน `MSH_CMD_EXPORT`) |
